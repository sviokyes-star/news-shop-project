# Перенос сайта на свой сервер

Инструкция для VPS с Ubuntu. Выполняй шаги по порядку, команды копируй целиком.

Что получится в итоге: на твоём сервере работают сайт, все 22 функции,
база данных, хранилище картинок и бесплатный SSL-сертификат.

---

## Шаг 1. Направь домен на сервер

В панели управления доменом создай A-запись:

| Тип | Имя | Значение          |
|-----|-----|-------------------|
| A   | @   | IP-адрес сервера  |
| A   | www | IP-адрес сервера  |

Изменения расходятся до 1 часа. Без этого SSL не выпустится.

---

## Шаг 2. Подключись к серверу

С компьютера (Windows — PowerShell, Mac/Linux — терминал):

```bash
ssh root@IP_АДРЕС_СЕРВЕРА
```

Пароль провайдер прислал на почту.

---

## Шаг 3. Скачай проект на сервер

```bash
apt update && apt install -y git
git clone АДРЕС_ТВОЕГО_РЕПОЗИТОРИЯ /opt/app
cd /opt/app/selfhost
```

> Репозиторий подключается в редакторе: **Скачать → Подключить GitHub**.

---

## Шаг 4. Первый запуск установщика

```bash
sudo bash install.sh
```

Скрипт поставит Docker, настроит файрвол и создаст файл настроек `.env`,
после чего остановится и попросит его заполнить.

---

## Шаг 5. Заполни настройки

```bash
nano .env
```

Заполни:

- `DOMAIN` — твой домен, например `mysite.ru`
- `POSTGRES_PASSWORD` — придумай длинный пароль для базы
- `AWS_SECRET_ACCESS_KEY` — придумай длинный пароль для хранилища
- `STEAM_API_KEY`, `GAME_SYNC_KEY`, `BATTLENET_CLIENT_ID`,
  `BATTLENET_CLIENT_SECRET` — перенеси значения из настроек проекта
  на платформе (раздел с секретами)

Сохранить: `Ctrl+O`, `Enter`, выйти: `Ctrl+X`.

---

## Шаг 6. Запусти всё

```bash
sudo bash install.sh
```

Проверь, что функции живы:

```bash
curl -s http://localhost/api/health
```

Должен появиться список из 22 функций.

---

## Шаг 7. Перенеси данные из старой базы

Данные (пользователи, балансы, покупки) переносятся дампом.

1. Выгрузи базу со старого места — на своём компьютере:

```bash
pg_dump "СТРОКА_ПОДКЛЮЧЕНИЯ_К_СТАРОЙ_БАЗЕ" > dump.sql
```

> Строку подключения возьми из секрета `DATABASE_URL` в настройках проекта.

2. Скопируй дамп на сервер:

```bash
scp dump.sql root@IP_АДРЕС_СЕРВЕРА:/opt/app/selfhost/backups/
```

3. На сервере загрузи его в новую базу:

```bash
cd /opt/app/selfhost
bash restore.sh backups/dump.sql
```

В конце выведется список таблиц — значит данные на месте.

**Важно:** делай перенос, когда на сайте нет активности, иначе свежие
покупки, сделанные после выгрузки, потеряются.

---

## Шаг 8. Собери сайт и положи на сервер

Сначала переключи сайт на свой сервер. В папке проекта создай файл
`.env.production` со строкой (подставь свой домен):

```
VITE_API_BASE=https://твой-домен/api
```

Это единственное место, где задаётся адрес функций. Пока строки нет,
сайт работает со старыми адресами на платформе — удобно для отката.

Затем собери и загрузи:

```bash
npm install
npm run build
scp -r dist/* root@IP_АДРЕС_СЕРВЕРА:/opt/app/selfhost/site/
```

Либо собери прямо на сервере, если установлен Node.js.

Открой `https://твой-домен` — сайт должен работать, SSL выпустится
автоматически за 10–60 секунд.

---

## Шаг 9. Включи автоматические бэкапы

```bash
crontab -e
```

Добавь строку (копия базы каждую ночь в 4:00, хранится 14 дней):

```
0 4 * * * cd /opt/app/selfhost && bash backup.sh >> /var/log/db-backup.log 2>&1
```

Разовый бэкап вручную: `bash backup.sh`

---

## Что важно знать про адреса функций

Раньше фронтенд обращался к адресам вида
`https://functions.poehali.dev/<длинный-код>`.

Теперь все функции доступны на твоём домене по понятным адресам:

```
https://твой-домен/api/news
https://твой-домен/api/shop-items
https://твой-домен/api/steam-auth
```

То есть `/api/` + имя функции.

Код сайта уже готов к переключению: все обращения идут через один
общий модуль. Достаточно задать `VITE_API_BASE` (шаг 8) — и сайт
начнёт работать с твоим сервером. Убрал строку — вернулся на платформу.

**Не забудь** обновить адрес синхронизации в файле `sync.json`
у CS2-плагина на игровом сервере — там тоже прописан старый адрес.

## Ежедневные команды

```bash
cd /opt/app/selfhost

docker compose ps               # что запущено
docker compose logs -f api      # логи функций
docker compose restart api      # перезапустить функции
docker compose down             # остановить всё
docker compose up -d --build    # запустить после обновления кода
```

## Как обновлять сайт и функции

Порядок после любых правок в редакторе:

1. Правишь проект в редакторе как обычно
2. Изменения автоматически уходят в GitHub
3. На сервере выполняешь ОДНУ команду:

```bash
cd /opt/app/selfhost && bash update.sh
```

Скрипт сам поймёт, что изменилось: тронул функции — пересоберёт их,
тронул страницы — пересоберёт сайт. Занимает 1–3 минуты.

Если нужно пересобрать всё принудительно:

```bash
bash update.sh --all
```

**Важно про новые функции.** Новая функция подхватывается автоматически —
никаких настроек не нужно. Она сразу доступна по адресу
`https://твой-домен/api/имя-функции`. В коде сайта обращайся к ней как
к остальным: `func2url['имя-функции']`.

**Важно про базу.** Если в редакторе менялась структура таблиц, применить
изменения на своём сервере нужно вручную — миграции автоматически
не применяются. Файлы лежат в `db_migrations`, применить конкретный:

```bash
docker compose exec -T db psql -U appuser -d appdb \
  -c "SET search_path TO t_p15345778_news_shop_project;" \
  -f - < ../db_migrations/V00XX__название.sql
```

## Если что-то не работает

**Сайт не открывается / нет SSL**
Проверь, что A-запись домена указывает на IP сервера:
`dig +short твой-домен`. Логи: `docker compose logs caddy`

**Функции отвечают ошибкой**
`docker compose logs api` — там будет причина.
Чаще всего не заполнен ключ в `.env`.

**База не принимает данные**
`docker compose logs db`. Проверь, что пароль в `.env` не содержит
символов `$`, `"` и пробелов.
